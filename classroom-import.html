Google Classroom → Blogger

Post once in Classroom and let it appear on the classroom board by itself.

How the pieces fit

The board cannot read Google Classroom directly — Classroom keeps your courses private, and this page is just a web page with no server behind it. Blogger is the bridge: a small script running in your Google account copies each day's Classroom items onto your blog, and the board reads the blog. Everything below happens in your own Google account. You only do it once.

Prefer to just write the posts yourself? You do not need any of this — post on your blog, and connect it in the app's Class blog box.

  1. Make sure the blog is public

    In Blogger, open Settings → Permissions → Reader access and set it to Public. The board reads your blog the way any visitor would, so a private blog is invisible to it.

  2. Start a script in your Google account

    Go to script.google.com and start a new project. Give it a name like Classroom to Blogger. Delete the few lines already in the editor.

  3. Paste the script

    Copy this and paste it into the empty editor. Then change the BLOG_URL line near the top to your own blog's address, and press Save.

  4. Let it read Classroom

    In the left sidebar, next to Services, click +. Choose Google Classroom API and click Add. Leave the identifier as Classroom.

  5. Let it write to Blogger

    Open Project Settings (the gear) and tick Show "appsscript.json" manifest file in editor. Go back to the editor, open appsscript.json, and replace what is there with this. Change the time zone to yours if it differs, then save.

    appsscript.json 
    {
  "timeZone": "America/Los_Angeles",
  "dependencies": {
    "enabledAdvancedServices": [
      {
        "userSymbol": "Classroom",
        "serviceId": "classroom",
        "version": "v1"
      }
    ]
  },
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/classroom.courses.readonly",
    "https://www.googleapis.com/auth/classroom.announcements.readonly",
    "https://www.googleapis.com/auth/classroom.coursework.students.readonly",
    "https://www.googleapis.com/auth/blogger",
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/script.scriptapp"
  ]
}

  6. Run it once, then set it to run every morning

    Pick publishToBlogger from the function menu at the top and press Run. Google will ask you to allow it — that is it asking for the permissions from the previous step, and it goes to your script, not to anyone else. It will warn that the app is unverified; choose Advanced → Go to (your project name), since the project is your own.

    Check your blog: there should be one post per course. Then pick installDailyTrigger from the same menu and press Run once. From then on it posts on its own each morning at about 6am.

  7. Connect the blog to the board

    Back in the schedule app, open the setup screen and paste your blog address into Class blog. That is the last step — the board picks it up from there.

Getting posts onto the right period

Each post carries a label, and the board puts a labelled post on the matching period. The script labels every post with its Classroom course name, so if your course names match the names you typed into the app, it already lines up. Anything the board cannot match to a period shows as a general announcement instead — which is what you want for a fire drill or a reminder about picture day.

Blogger labelWhere it lands
Algebra IThe period you named "Algebra I"
Hour 3, 3rd Hour, Period 3All land on Hour 3
Instruction 2The elementary block of that name
no label, or anything elseThe announcements strip

If a course name does not match a period name, map it in the COURSE_LABELS line near the top of the script.

If something goes wrong

The board stays empty. Open your blog in a private window. If you cannot see it without signing in, it is not public yet — step 1.

The script says it cannot find the blog. The BLOG_URL line needs the address you actually visit, including https://, and nothing after the host.

Nothing gets posted. The script only posts a course that has an announcement from the last few days or an assignment due today or tomorrow. Set DRY_RUN = true and run it again — the Execution log will show what it found.

You want to stop it. Run removeTriggers, or delete the script project. Removing the blog from the app's setup screen stops the board reading it either way.
